# 07: 指标设置、持久化与性能条布局

**What to build:** 用户可配置显示哪些指标以及性能条外观和刷新速度；更改立即反映在单行性能条中，并在重启后保留。

**Blocked by:** 02: 原生性能条窗口交互与 DPI；04: CPU 与内存指标；05: 物理网卡网速；06: GPU 与 ACPI 温度。

**Status:** ready-for-human

- [x] 设置提供 CPU、内存、GPU、网络和时间五项开关；默认全开，GPU 标注“仅 NVIDIA”。
- [x] 设置提供快刷新 1000/2000/5000ms（默认 1000ms）和慢刷新 3000/5000ms（默认 3000ms）。
- [x] 设置提供 system/dark/light 主题、背景不透明度 0.20–1.00（步长 0.05，默认 0.72）和字号 10–18 DIP（默认 12）。
- [x] 设置更改立即应用、持久化并显示约两秒“已保存”；数值范围校验、损坏配置备份并恢复默认，文件更新具备原子性。
- [x] 性能条按 CPU、内存、GPU、网络、时间顺序显示可见段；相邻可见段之间才显示分隔线。
- [x] 字体和布局遵循规格的间距、等宽数字、缺失值和宽度变化规则；数字刷新不造成窗口反复缩放。

## 实现与自动验证

- Core 将完整设置保存在 `StartupShellController.Settings` 不可变快照中；设置窗经控制器深合并可编辑字段，不能补丁写入窗口位置、贴边状态或菜单专属选项。保存失败时控制器不发布新值，UI 显示失败并恢复上次已保存值。
- 启动时快慢采样器读取持久化刷新周期；运行中修改周期会取消当前代际并以新周期立即补采样，采样 gate 保持共用以避免旧周期在途读取与新代重叠。设置变化不会解除隐藏或原生拖动期间的暂停。
- Windows 配置文件位于 `%LOCALAPPDATA%\PerfMonitorWpf\settings.json`，包含 `schemaVersion: 1`，不复用旧版配置目录。写入先落同目录临时文件并 flush，再用文件替换；首次保存用同卷移动。JSON、schema、范围或 opacity 步进损坏时保留 `.corrupt-<UTC时间>` 备份并写回默认值。
- 设置表单中的不透明度改变值按十进制 `0.20 + 0.05n` 量化；为遵守规格默认值，首次加载的 `0.72` 会原样显示和保留，直到用户操作滑块。
- 性能条按 CPU、内存、GPU、网络、时间排列；VM 按可见段计算分隔线。读数使用等宽字体，窗口只在同一指标/字号组合下扩大；指标组合或字号改变时重新测量。时间使用独立的一秒本地时钟。
- 验证命令：`dotnet test PerfMonitor.sln --no-restore --verbosity minimal`，Core 50/50、Windows 9/9 通过；`dotnet build PerfMonitor.sln --no-restore --configuration Debug --verbosity minimal` 与 `... --configuration Release ...` 均为 0 warning、0 error。Core 周期测试验证持久化的 5000ms 首次采样节奏、运行时快慢周期切换的下一次采样时刻，以及隐藏/原生拖动期间周期变化不恢复采样；重复启动重新显示性能条后立即恢复采样。
- 进程级 smoke：Debug EXE 启动后存活超过 8 秒；本次未写入用户配置文件。`CloseMainWindow()` 没有可关闭的主窗口句柄，之后为清理本次 smoke 进程而终止它；这不作为正常退出验收通过证据。

## 待人工复验

当前桌面自动化状态没有可绑定的 Windows 原生应用窗口，因此没有把视觉和设置窗交互标记为已通过。请在真实桌面验证：

1. 打开设置，确认五项开关、NVIDIA 注记、刷新选项和默认值；更改指标后检查性能条即时更新，重启后检查配置回读。
2. 调整主题、不透明度与字号，确认卡片背景变化而文字不变透明；验证保存提示约两秒后消失，保存失败显示失败且不显示成功。
3. 使用一次性测试配置验证非法/损坏文件会备份并恢复默认，不触碰旧版配置。
4. 隐藏任意指标组合检查顺序与“只在相邻可见段之间”的分隔线；改变数字宽度确认窗口不缩放抖动，改变字号/指标组合后确认宽度可重新缩小；全关时仍保留至少 64 DIP 命中区。
5. 在不同 DPI、混合 DPI 和字体回退环境检查文字、圆角、高度、间距和设置窗滑块/组合框的实际观感；system 主题切换后确认主题更新。
