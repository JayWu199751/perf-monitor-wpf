# 性能小窗 WPF 等价重写规格

版本：1.0，确认日 2026-10-05。
Status: ready-for-agent
本文件是当前实现的产品行为合同；交接包中的技术建议仍需按下文验证。用户已确认的提权策略与“不导入旧配置”决定在此覆盖准备材料中的待确认建议。

## 问题陈述

用户需要一个常驻托盘、低打扰、低资源消耗的 Windows 11 性能小窗。现有 Electron 应用已形成具体的指标口径、布局、窗口交互和设置行为，重写必须保留这些可观察功能，不能用近似读数或删除功能换取实现简单。

## 解决方案

以 C#、WPF 和原生 XAML 为基础，在当前 PerfMonitor-WPF 工作区实现 Windows 11 x64 原生应用。应用保持中文单行性能条和托盘体验，并以同机整进程树 Private Bytes 测量持续降低内存占用；所有未验证的 WPF、Win32、DPI、提权和资源结论都必须用规定证据标记，不能从 HTML 原型或旧版历史数字推断通过。

## 实施决策

### 模块边界

- Core 承载 Settings、指标快照、算术/几何规则、显隐与窗口状态控制、设置窗生命周期和采样编排；规则不依赖 WPF 或 Win32。
- Windows 承载系统指标来源、WMI、网卡表、前台窗口、显示器、计划任务、权限令牌、单实例通知、托盘资源和 native 资源释放。
- App 承载 WPF/XAML、ViewModel、应用生命周期、组合根及原生窗口消息接线。
- 以 Core.Tests 验证最高层行为合同，以 Windows.Tests 验证真实 Windows adapter；不按每个类拆分生产项目。


### F01 平台、启动与实例

- Windows 11 x64；C# + WPF，原生 XAML 界面，GUI 程序无控制台。普通启动只显示小窗和一个托盘图标。
- 小窗无标题栏、无任务栏按钮、透明宿主、始终置顶；设置窗为普通可交互窗口。普通自动显示不抢焦点，用户明确唤起允许聚焦。
- 单实例覆盖普通与管理员启动的协调：新实例通知旧实例手动显示后退出。不能把单实例问题转成两个权限等级各有一份实例。
- 退出入口在共享菜单；设置窗的关闭动作不退出应用。系统注销/关机同样干净结束。

### F02 CPU 与内存

- CPU 百分比：累计全机 CPU 时间差分，整数 0–100；首次基线返回 0，读取失败返回缺失。
- 内存段只显示使用百分比。快照保留已用/总量 GiB（历史字段名 `Gb`，不是 gigabit）。旧实现先四舍五入 GiB 再算百分比会损失精度；重写使用物理字节原值计算百分比、展示时取整，这是明确的兼容性修正。
- 任何 Win32/WMI 读取不阻塞 UI 线程。CPU、内存、GPU 百分比和温度，以及网速的一位小数，沿用旧实现 Math.round 的中点语义；实现必须明确复现，不能依赖 .NET 默认银行家舍入。

### F03 GPU 与温度

- NVIDIA：GPU 使用率、专用显存已用/总量百分比、GPU 温度，均为整数；顺序为主利用率、次级显存、次级温度。
- 保持 `nvidia-smi --query-gpu=utilization.gpu,memory.used,memory.total,temperature.gpu --format=csv,noheader,nounits` 的功能口径，进程无控制台，5 秒超时。超时、命令缺失、非法输出、AMD/Intel-only → GPU 相关值缺失。
- 多 NVIDIA 卡现有解析没有明确合同；默认显式选择首条有效设备记录并记录此选择，禁止把多行 CSV 当单个字段解析。多卡汇总/选择不是既定功能。
- CPU 温度读取 `root\WMI` 中 `MSAcpi_ThermalZoneTemperature.CurrentTemperature`，单位为十分之一 Kelvin，转 Celsius 后取整。这是 ACPI 热区温度，不能承诺等于 CPU 核心温度。
- 非管理员、无热区、访问拒绝、查询失败显示 `--`；不影响其他指标。多热区沿旧实现最大有效值口径，细节对照冻结 WMI 源码及测试。
- 温度单位保持 `°`，位于最大主读数 cap 线上方区域；缺失态 `--°` 的小圈位置保持稳定。

### F04 网速口径

- `GetIfTable2Ex` 读取累计 64 位收发字节计数；仅 up（`IfOperStatusUp = 1`）且非 loopback 的行进入基础候选。
- 优先只取 `PhysicalMediumType != Unspecified` 的物理网卡；若一个物理候选也没有，则退回基础候选全集，保留现有明确兜底及其可能偏大的局限。
- 每一轮分别对候选算差分，选择**收发速率之和最大的一行**；下行和上行必须来自同一行。禁止把多个 filter 子接口累加，也不能分别取最大的上下行。
- 以实际两次采样的单调时间差摊平，字节/秒再除 `1024²`，界面仍按既有 `MB/s` 命名并保留一位小数（兼容名称，实际是二进制换算）。
- 首轮、新网卡无基线、非正时间差 → 0；计数重置变小的方向本轮按 0；读表失败 → `--`。保留全部基础行基线，候选筛选变化不会丢失之前有效基线。
- 暂停后的首次恢复建立新基线，下一轮再算有效速率，防止把长时间暂停误算成瞬时爆量。这是明确的稳健性修正。

### F05 快照与调度

- 快照字段：`cpuPct?`、`cpuTemp?`、`memUsedGb?`、`memTotalGb`、`memPct?`、`gpuPct?`、`gpuMemPct?`、`gpuTemp?`、`netDownMBs?`、`netUpMBs?`、`ts`。C# 命名可用 PascalCase，序列化旧配置/夹具时保持映射。
- 快通道 CPU/内存/网络默认 1000ms，可选 1000/2000/5000；慢通道 GPU/温度默认 3000ms，可选 3000/5000。
- 快慢独立读取，失败只影响对应源，合并为不可变最新快照；读数缺失区分真实 0。
- 同一通道采样不重叠；重启/停止使用代际或取消令牌隔离在途结果，旧任务不能写回新服务，也不能在退出后投递。
- 小窗隐藏时暂停快慢采样，显示立即补采样；全屏 watcher 要继续观察，否则无法自动恢复。原生拖动期间暂停采样/渲染投递，单槽保留最新在途快照，松手只投递最新并补采样。暂停恢复期间界面保留上一代已知读数直到新采样到达，不闪现缺失占位（见 docs/adr/0006）。
- 时钟本地 `HH:mm:ss`、24 小时格式、每秒独立更新；关闭时取消自己的 timer。无需启动指标源来更新时钟。

### F06 性能条布局

- 单行，顺序 CPU → 内存 → GPU → 网络 → 时间；只在可见相邻段之间绘制细分隔线，末段无分隔线。
- CPU 为使用率 + 温度；内存为百分比；GPU 为利用率 + 显存百分比 + 温度；网络为 `↓ 下行 MB/s ↑ 上行 MB/s`；时钟不加多余图标。
- 性能条五个段均不显示指标图标，不留图标占位或专属间距；设置窗不再提供「显示图标」分组。保留文字标签、读数、单位和网络上下行箭头；旧配置中的图标偏好忽略，保存时移除，其他设置保留（2026-10-09 确认）。
- 主读数最醒目，标签与辅助读数层级分明，等宽数字；普通百分比整数，网速一位小数，缺失文本 `--` 稍弱化。
- CPU、内存、GPU 主占用百分比与时间使用同一正文颜色：深色主题为 `#F3F5F7`，浅色主题为 `#1A1D22`，跟随系统主题时随有效主题更新；缺失值继续弱化显示。显存百分比沿用正文色，温度、标签和网络箭头颜色不变（2026-10-09 确认）。
- 自然内容宽，无定宽数字槽。字号 fs 对应间距：标签到读数约 `0.58fs`、读数间约 `0.50fs`、跨段约 `0.83fs`，数字与单位约 1 DIP；圆角约 `0.8fs`。字体变更后重新视觉测量。
- 宿主窗口宽度跟随内容自然宽，可增可减；个位数读数用等数字宽占位符，宽度变化集中在位数增减边界（如 9.9→10.0、99→100）。高度允许双向变化，重复相同尺寸不重摆窗口。行内居中开启时宽度变化立即按实际宽度重新居中。
- 所有段关闭仍保留最小 64 DIP 可拖动/右键命中区，用户可从托盘重新打开设置；不自动打开某个段，不新增标签污染界面。
- **卡片高度不是常量**：最大字号主数字与时钟的可见墨迹上下各留 6 DIP 到可视边框；安全边框另计。中文标签、箭头、缺失态不能决定高度，却必须完整不裁切。
- 混合字号按主体中线共线；`°` 按 cap 线例外；设置窗普通文字不套性能条光学校正。WPF 用本地字体与真实像素建立自己的度量，不复制 Chromium 的 a/ρ 表或 CSS `vertical-align`。

### F07 拖动、贴边与位置

- 小窗任意可见/透明命中区域可拖动，采用原生移动，右键保持菜单语义。移动中跟手，松手后结算。
- 工作区四边阈值 8 DIP，支持四角组合；掩码规范顺序 top/bottom 在 left/right 前；取消方向保持现有「向屏幕内离开阈值」语义。
- 可视卡片紧贴工作区边，保留约 1 DIP 安全边框；如宿主有透明额外边距，落位时把相应透明部分推出工作区。最大字样 6 DIP 边距与宿主透明边距是两个不同概念。
- 位置与贴边掩码唯一由窗口 controller 写入，设置表单不能写；原生实际尺寸/位置读取后结算，重入门控避免摆窗触发移动事件递归。
- 位置 500ms 防抖持久化；期间改其他设置合并最新位置；退出/销毁 flush 最后位置。创建期临时位置不能覆盖待恢复位置。
- 多显示器按卡片中心解析目标显示器，处理负坐标与不同 DPI；工作区/DPI/分辨率变化重新落位；目标屏消失时夹回现有显示器可见工作区。
- 当前只维护**一份最后位置**。README 的「每屏各自记忆」缺少实际模型支撑，先不发明逐屏位置档案。

### F08 任务栏行内与行内居中

- 这是同一张性能卡覆盖在任务栏之上的落点，用户拖入即可；不做 appbar、reparent、独立任务栏模式或另一套布局。
- 行矩形从显示器 bounds 与 work area 差分派生；只支持水平顶/底带，左右侧任务栏不支持此落点；无占位带时保持普通贴边。
- 卡片中心位于行内（左闭右开）并满足对应顶/底贴边落点时，卡片垂直居中到行；默认 x 来自用户拖动。
- 菜单「任务栏内水平居中」为唯一开关入口，持久化 `centerInTaskbarRow`。开启后行内横向由规则独占：拖动跟手，松手弹回行矩形水平中心。开启立即结算，关闭原地不动；行外不生效。
- 居中参照是整个显示器宽度对应的行矩形，不避让开始按钮/托盘/应用图标；覆盖处会拦截点击，保留已确认的代价。
- 真实任务栏切应用后能恢复可见性。旧版守卫 30ms / 状态与句柄 300ms 慢刷新；WPF 先真机验证等价的 z-order 方案，必要时使用该节奏。隐藏时停止，悬浮态跳过原生遮挡检查，explorer 重启能刷新句柄。
- 判据为根窗口句柄归属或 z 序；不能按随数字变化的截图判遮挡。不能把 `Topmost=true` 当作任务栏行内已验证。

### F09 显隐与全屏自动隐藏

- watcher 默认每秒观察其他前台窗口；排除本应用、桌面 Progman/WorkerW、任务栏 Shell_TrayWnd（含相应副屏系统类）；普通带标题栏/边框最大化不等于全屏。Chrome F11 即使带 WS_MAXIMIZE 仍须识别。
- 全屏矩形按统一物理坐标与对应显示器比较，边界容差 2 物理px；DPI 合同明确后避免对混合坐标胡乱乘缩放。
- 自动隐藏仅产生于「进入全屏」状态边沿；持续全屏不重复覆盖用户选择。自动退出全屏恢复不抢焦点。

| 事件/前态 | 行为 |
| --- | --- |
| 可见且非手动隐藏 → 进入全屏 | 隐藏，标记自动隐藏 |
| 自动隐藏 → 退出全屏 | 显示，清自动标记 |
| 手动隐藏 → 全屏进出 | 保持隐藏 |
| 自动隐藏 → 手动显示 | 显示并清两种隐藏标记；同一全屏周期内保持显示 |
| 手动显示后 → 退出全屏 | 保持显示，不重复显示/聚焦 |
| 手动显示后 → 新一轮进入全屏 | 恢复正常自动隐藏规则 |
| 任意隐藏 → 重复启动明确唤起 | 走手动显示入口 |

- 关闭全屏自动隐藏时，若当前只因自动原因隐藏，恢复显示；手动隐藏保持隐藏。这是重写的明确状态完整性修正。

### F10 托盘、共享菜单与透明显示

- 托盘 tooltip「性能小窗」，左键单击显隐；右键与性能条右键共用命令模型和勾选真值。
- 顺序：`显示/隐藏小窗`、`打开设置`、`任务栏内水平居中`（勾选）、`透明显示`（勾选）、分隔线、`退出`。右键不能先触发拖动，也不能因两条消息弹两次菜单。
- 透明显示只移除背景、描边/阴影、分隔线、模糊等非文字视觉元素；指标文字、箭头、时钟及布局命中区域保留；不是整窗 opacity=0，也不是鼠标穿透。
- 保留描边方框应用图标和深/浅托盘图标；有效浅色主题用黑图，深色用白图；主题/DPI 改变更新，16/20/24/28/32 物理px 资源优先匹配。
- explorer 重启后重新注册托盘；释放图标/HICON/菜单资源，无幽灵图标。

| fontSize | 12 | 10–18 DIP，步长 1 |
| theme | system | system/dark/light |
| widget | 初始由窗口落位策略确定 | x/y/docked，仅 controller 更新 |

- 设置四组：显示指标、刷新率、外观、行为；顶部标题「设置」。GPU 行注明「仅 NVIDIA」。改变后即时生效并持久化，显示「已保存」约两秒。
- 表单与菜单都使用中央不可变 Settings 真值，不持有分叉状态；指标补丁深合并，位置写入受控；菜单专有开关不接受表单通用补丁。
- 开机自启失败不能显示成功。WPF 增加输入范围验证、原子文件替换、损坏文件备份/恢复默认，属于配置可靠性修正。
- 新应用使用独立的用户级配置目录并加入 schemaVersion；不读取、导入或迁移旧版配置；新应用只读写自己的配置，不改写或删除旧版配置。相同用户的普通与管理员进程解析到同一新配置目录。
- 主题即时更新两个窗口和托盘；system 监听 OS 有效主题。背景不透明度仅改变卡片底色，不让文字一起变透明；透明显示时保留该值供退出时恢复。
- 设置窗懒创建；关闭即隐藏；5 分钟闲置后释放实例，下次重建；重新打开取消回收。退出/注销放行关闭。尺寸按内容与当前屏工作区确定，放得下不强制滚动，短屏能滚动访问所有行，不照抄旧版 880 高度。

### F12 自启、提权与发布

- Debug 以普通权限启动且不弹 UAC。Release 使用 asInvoker；每次启动时若当前进程未提权，自动发起一次 runas 提权尝试，不在同一启动过程中重试。用户拒绝或提权启动失败时，当前普通权限实例继续运行，CPU 温度按缺失值显示；提权成功后跨权限完成单实例交接，并用启动标记避免循环提权。
- token 检测真实 elevation，不能依赖 `net session` 或按用户组猜测；提权与实例交接顺序避免新旧实例互锁/双开。
- 开机自启采用当前用户登录触发的最高权限计划任务，命令路径正确转义，静默 GUI，不用 HKCU Run 启动一个需要 UAC 的 exe。
- 创建/删除任务必须按系统实际结果回写；Debug 不修改系统自启。新应用使用独立于旧版的自启任务名，只创建、查询和删除自己拥有的任务；不扫描、迁移或删除旧版计划任务及 Run 项。
- 发布产物为可运行 win-x64 Release（自包含或依赖框架方式在启动时确定），含图标、权限说明、卸载/清理自启方法、构建命令与版本信息。单文件裁剪、安装器格式按实测决定；自用，无分发签名需求。

### F13 尽可能低的内存占用（新增硬约束）

- 在满足F01–F12与已批准视觉/交互合同的方案中，优先选择经实测私有内存更低的方案；低内存是架构、数据源、UI、后台调度与发布验证的共同决策条件。
- 内存验收统计整棵app进程树的Private Bytes，包含GPU采样子进程、打开/隐藏的设置窗及native资源；报告MiB（除1024²）。工作集、安装包大小、单一进程名筛选、仅托管堆都不能替代该口径。
- 同机同权限/刷新/指标设置，旧版和WPF各跑至少3轮：稳定态私有内存均值及P95必须低于现版的对应配对统计，峰值不得高于现版；若差异在测量噪声内，补测确认，不能宣称已达成。历史107.2MB不能直接作为当前上限。
- 先记录真实基线与候选方案，再形成更低的具体MiB优化目标和取舍证据；不预填未测出的绝对数字。没有低于同机现版的证据，交付状态是「内存约束未满足/未验证」。
- 常驻代码使用必要的轻量依赖、按需初始化、有限缓存、可释放native/图形/托盘/WMI资源、无重叠采样和有界在途任务；避免为小工具引入大型UI库、WebView/Chromium、通用宿主与不需要的监控管线。
- 隐藏暂停采样、退出清理子进程，设置窗5分钟回收后释放所有订阅/窗口引用；只变化的内容才刷新UI，字体/Brush/格式化度量适当复用，不以每秒强制GC作为省内存方案。
- 完成1小时稳态、50轮设置开关与20轮隐藏/显示压力验证；回收/稳定后内存平台不持续抬升。若涨幅接近测量噪声，结合重复实验、托管/native分配证据确认；泄漏未排除不能通过。
- 更低内存的数据源或渲染方案可评估，但必须保持数据口径与完整功能并以探针/ADR记录。不得把安装包更小、关闭GPU加速或单文件发布直接当作运行内存更低的证据。
- 每项优化与测量都保留方案、Private Bytes、CPU变化、启动/拖动体验和功能矩阵证据；不以其他明显退化换取数字。

## 测试决策

- 自动化测试采用一个 Core 级用户可见行为合同作为唯一主接缝，通过可替换的时钟、数据源与窗口能力覆盖采样编排、设置、显隐、几何和状态转移。测试真实输入和外部可观察结果，不复制 XAML 属性，也不按内部类拆分合同。
- Windows 集成验证 P/Invoke 结构与资源释放、WMI、计划任务、权限令牌、托盘与单实例消息；真实桌面/硬件验证透明合成、任务栏遮挡恢复、混合 DPI、多显示器、ACPI 温度和登录自启。
- 按验收矩阵分别记录自动化（A）、Windows 集成（W）和真实桌面/硬件人工验证（M）的命令、环境和证据。浏览器模拟不能替代 WPF 真机证据。
- 温度、GPU、透明、提权、自启或目标 DPI 硬件不可用时标为“未验证”并给出复验步骤。资源测试按整棵应用进程树统计 Private Bytes，包含短命 GPU 子进程。
- 当前仓库没有 WPF 实现或对应测试先例；旧 Electron 源码与测试仅作为行为兼容参考，不代表 WPF 验收已通过。验收编号 A01–A46 的每项必须有结果或明确偏差。

## 补充说明

### 已确认决定

- 当前 PerfMonitor-WPF 工作区是目标实现仓库；冻结 Electron 源码只用于行为与兼容性核对。
- Release 采用 asInvoker；每次未提权的 Release 启动自动尝试一次 runas，同一次启动不重试；拒绝或失败时继续普通权限运行，温度显示为缺失。
- 不实现旧版配置导入或迁移。新应用不读取、改写或删除旧版配置，也不扫描、迁移或删除旧版自启任务/Run 项；两代应用使用独立配置和自启命名空间。
- 用户给定的字号、默认设置、网速筛选/换算和 F13 内存验收口径均为既定输入，不需要再次确认。
