# 尽可能低的内存占用：实施与验收

用户于2026-10-03追加要求。权威合同为 `spec.md` 的F13；本文件说明如何实现与测量。完整功能与低内存要同时满足，性能条和设置窗不能以删功能换低数字。

## 先基线，再优化

1. 在目标机器记录当前Electron版的实际进程树与Private Bytes。使用同一指标组合、快1s/慢3s、字号12、权限、GPU与桌面/DPI。不能把历史107.2MB复制成当前值。
2. 早期可运行WPF切片就记录相同口径，逐票保留增量。先确定主要占用来自托管对象、native/图形资源、WMI、字体或GPU采样子进程，再挑最有收益的方案。
3. 以完整功能相同为前提比较至少一个关键替代方案或一轮针对主要占用的优化。每次只改一个影响项，保存前后数据与功能验证。
4. 完整Release后旧/新各至少3轮配对，比较稳态均值、P95、峰值。满足F13的相对门槛后继续删去无必要常驻成本；最终给实际MiB目标和已达数据，不预设未经证实的绝对值。

## 具体约束

| 部位 | 优先做法 | 验证 |
| --- | --- | --- |
| 应用结构 | 必要依赖，简单组合根与明确MVVM；无需的Host/大UI库/WebView/监控管线不加载 | 依赖与已加载程序集、稳态Private Bytes |
| 设置窗口 | 懒创建、5分钟后释放窗口/订阅/引用，重建只保留Settings真值 | 50轮开关与回收后可达对象/句柄 |
| 数据采样 | 快慢串行、不重叠、取消/代际隔离；隐藏不继续轮询或积压任务 | task数、进程树、隐藏前后曲线 |
| native边界 | SafeHandle/finally释放表、COM/native句柄、HICON与hook；委托生命周期结束解除 | Handle/GDI/USER/COM与Private Bytes趋势 |
| UI刷新 | 只有变更才更新，复用Brush/字体/度量，缓存有上限 | 分配热点与每秒分配率，长时间曲线 |
| 文本 | 保留自然内容与五个像素判据，缓存按有效字号/字体/DPI有界 | 字号/DPI反复切换，不无限缓存每个读数 |
| GPU数据 | 先测nvidia-smi峰值/占空比；若是主要占用再评估等价的进程内来源 | 口径/权限/设备兼容性完整验证及ADR |
| 发布形式 | framework-dependent/self-contained/单文件/裁剪按实际支持与加载开销比较 | 运行Private Bytes，不能以包体积作结论 |
| 图形加速 | 透明渲染前提下比较必要方案，不照搬Electron关闭GPU结论 | 真alpha、CPU/拖动与内存一起测 |
| GC | 正常生命周期与有限分配；强制GC可诊断，不是常驻定时器 | 不存在生产周期GC掩盖持续增长 |

上述为选择原则，不要求为了少一个小库重写所有成熟基础设施。引入必要依赖时说明它解决的实际问题并测量。

## 场景与采样

| 场景 | 观察窗口 | 要报告 |
| --- | --- | --- |
| 冷启动 | 前30秒 | 峰值、到可读快照时间 |
| 可见稳定态 | 预热30秒后至少5分钟 | 整树均值/P95/峰值、父与子进程分解 |
| 隐藏 | 至少2分钟 | private变化、采样与子进程是否停止 |
| 设置打开/关闭 | 打开后、关闭后即时、5分钟回收后 | 保留和释放成本 |
| 任务栏行内/拖动 | 各至少2分钟 | native守卫/移动状态增量，CPU影响 |
| 长时间运行 | 1小时 | 分段均值/趋势、对象/句柄是否持续增长 |
| 压力 | 50轮设置开关/回收、20轮显隐；适当切字号/DPI | 最终平台能否返回稳定区间 |

进程集合从app根PID按父子关系追踪，处理短命子进程和退出，不能只按exe名字筛。基准采样建议1秒；额外以50–100ms短窗口捕获GPU命令突发峰值，两版本用相同采样设置。测量器在外部进程运行，自身不计入app树；记录测量扰动。所有数字用MiB，Private Bytes≠Working Set≠GC heap。

保持同机电源模式、外部负载与采样设置，轮次交错执行旧/新以减小时间偏差。差异在噪声内时延长窗口或增加轮次，不能挑最小单次数字比较。
