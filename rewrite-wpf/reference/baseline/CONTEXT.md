# 性能小窗（Win11 Perf Monitor）

Windows 11 桌面性能检测小工具：常驻托盘的透明置顶小窗，实时显示 CPU/内存/GPU/网速/温度等指标。自用工具，无分发 scope。

## Language

**小窗**:
置顶显示的横向状态条窗口，展示各项性能指标。
_Avoid_: 状态条, widget, 悬浮窗

**透明显示**:
小窗与托盘共用右键菜单中的持久化显示开关。开启时仅指标相关文字可见，包括名称、读数、单位、缺失占位、时间和网速方向字符；卡片背景、描边、阴影、模糊、分隔线等非文字视觉元素透明。它只改变视觉呈现，不改变拖动和右键交互；关闭后按「背景不透明度」设置恢复卡片背景。
_Avoid_: 文字模式, 点击穿透

**时间指标**:
小窗最右侧显示的本机本地时间，采用 24 小时制 `HH:mm:ss`，可像其他显示指标一样独立显示或隐藏。
_Avoid_: 时钟, 当前时间

**设置窗**:
配置小窗行为（主题、自启、刷新间隔等）的窗口，关闭即隐藏。
_Avoid_: 设置窗口, settings

**常驻托盘**:
关闭全部窗口后进程仍存活于系统托盘，退出只经托盘菜单。
_Avoid_: 后台运行, 最小化到托盘

**退出**:
唯一终止应用的方式：进程完全结束、托盘图标消失。
_Avoid_: 关闭应用, 终止进程

**关闭即隐藏**:
设置窗的关闭语义：隐藏并复用实例，而非销毁。
_Avoid_: 关闭窗口, dispose

**贴边悬靠**:
小窗拖到可用工作区（排除任务栏）边缘 8px 内时吸附到该边（可同时吸附多条边，如左上角）；吸附后窗口把卡片四周的透明边距推出屏幕，使**可视卡片**紧贴屏幕边（卡片自身仍保留 1px 透明安全边框）；从贴边方向拖离阈值即取消。贴上边有两个落点，另一个见**任务栏行内**。
_Avoid_: 磁吸, snap

**任务栏行内**:
小窗贴上边的第二种落点：卡片中心落在**任务栏行**（显示器边界与工作区边界之间那条水平带）内时，改为垂直居中到该行，即卡片覆盖在任务栏之上显示；横向位置默认仍由拖动决定，不做托盘对齐；开启**行内居中**时改为水平居中到该行。左右侧任务栏时该行是竖直的，不支持此落点。判据、可用档位与被否决的替代方案见 ADR-0005。
_Avoid_: 任务栏嵌入, 任务栏停靠, 内嵌模式, 任务栏模式

**行内居中**:
小窗停在**任务栏行**内时把卡片水平居中到该行的可选规则，经共享应用菜单的「任务栏内水平居中」开关持久开启。开启期间行内的横向位置由规则独占：拖动跟手、松手弹回居中，想自由摆位先关。居中参照是行矩形本身（= 显示器全宽），不做托盘或中部图标避让，盖住它们的代价是 ADR-0005 既认代价的延续。取舍见 ADR-0005 后续修正二。
_Avoid_: 任务栏居中, 居中模式, 自动对齐, 托盘对齐

**光学校正**:
让文字**主体中线**重合所需的位移：`vertical-align: calc(-1 * (a·(--fs) + ρ·1em))`，a 与 ρ 都无量纲。自 ADR-0006 修正三起，它只负责「各角色彼此共线」这一件事：卡片中心线由盒子自己给出（见**最大字样边距**），不再由校正量去凑。a 项存在是因为标签/次级读数/单位都被 `clamp()` 钉过档，它们与 --fs 的比例在若干档上是常数；ρ 项量「该 run 的主体中线离自身基线有多远」。全项目只有 `optical.css` 的 `.optical` 一处执行它，两张表由真像素反解。它只用于"同一段文字里混了多种字号"的场合：设置窗不接（实测接了反而变差）。唯一的例外是**上标单位**：形式照用，参照线换成 cap 线。
_Avoid_: 光学居中, 视觉对齐补偿, 像素微调, 手调常数

**墨迹中线**:
一段文字实际可见墨迹**外框**上下沿的中点，是"看着居中了"的判据的字面起点；它与基线、行盒中心、em 盒中心都不重合，差值由字体与字形集决定（`°` 是上标小圈、`--` 坐在数学轴上、`MB/s` 带降部斜杠，三者各要各自的 ρ）。量具量的就是这类实测墨迹量，不是任何推算值；但小窗共线实际参照的是**主体中线**——外框会被细笔画单方面拖走。
_Avoid_: 基线, 中线, 视觉中心, 行盒中心

**主体中线**:
一段文字**去掉细笔画之后**的墨迹上下沿中点，是小窗共线判据实际参照的那条线。它与**墨迹中线**（外框中点）的区别只在带降部/带细笔画的角色：`MB/s` 的斜杠只占取值带一两列却把外框下沿拖下一整格，按外框居中会让 M B s 骑在数字的 cap 线上——用户看到的「数字和单位不居中」就是这个。细笔画判定：覆盖率 ≥ 20% 峰值的最长连续行段；主体撑不满外框 75% 高度就退回外框（`↓↑` 是一根通高的细杆，否则主体会塌成箭头那三行）。见 ADR-0006 修正四。
_Avoid_: 外框中线, 重心, 视觉重心, 加权中心

**上标单位**:
`°` 这一档单位记号。它**不参与共线**：归位参照是**最大字样**的墨迹上沿（cap 线），不是那条中心线——上标记号的语义就是骑在自己那个数字的右上角，把它抬到中心线上正是用户报的「温度的单位应该在数字的右上角，你把它居中了」。名单只有一处，`electron/scripts/alignment/roles.cjs`；量具第 4 条判据（上标墨迹上沿离 cap 线 ≤1.5 设备px）与 `fit-rho.cjs` 的反解参照共用它，所以「谁豁免、谁改吃 cap 线」不会两处漂移。定律的形式一个字没动，换的只是该角色反解时对的参照线，因此执行处仍然只有 `.optical` 那一行。参照刻意取全条 bar 的最大字样而不是本读数自己的数字：缺失态那一格是 `--`，它的墨迹坐在数学轴上，跟着它走会让 `°` 随有没有数据上下跳。见 ADR-0006 修正五。
_Avoid_: 上标角标, 角标, 单位抬高, superscript 偏移

**最大字样边距**:
小窗卡片高度的唯一决定量：把内容盒裁到「字号等于 `--fs` 那批 run（主读数与时钟）的主体墨迹外框」，上下各再留 `WIDGET_EDGE_GAP` = 6 CSS px 到**可视边框**。于是卡高随字号呼吸（实测 20.8→26.4），而这一格距离与字号、DPI、用的是哪族字体都无关。卡片几何因此只有两个源头，都在 `optical.css` 的 `:root`：`--edge-gap`（= `WIDGET_EDGE_GAP`，目标那一格）与 `--edge-bleed`（抗锯齿让实测墨迹比「cap 顶 → 基线」这个裁切盒每边多出的那一小截，0.34 CSS px；它是 AA 的性质，与目标边距是几无关，所以改 `WIDGET_EDGE_GAP` 不动它）。参照刻意不是全条 bar 的墨迹并集——并集含中文标签与箭头降部，那些角色的比例本身随字体变，拿它当参照就等于把居中重新变成一张按字体拟合的表；并集只用作**裁切**判据。术语与实测见 ADR-0006 修正三，`WIDGET_CARD_HEIGHT` 因此只是首帧兜底初值，真值由渲染端上报。
_Avoid_: 卡片高度, 内边距, padding, 安全边距

**共享基线**:
整条 bar 处于单一 inline 格式化上下文时所有文字 run 共用的那条基线——行盒只有一个、基线只被 Chromium 吸附一次，所以 run 与 run 之间的中线差只剩墨迹量数之差，那正是光学校正能算掉的部分。它同时是光学校正 a 项的参照物，也是「小窗不许把文字 run 重新拆成独立 flex 项」这条形状约束的理由。
_Avoid_: 基线对齐, 同一条线, 底线, 共享行盒

**全屏自动隐藏**:
其他应用进入全屏（独占或无边框）时小窗自动隐藏，退出全屏自动恢复；用户手动隐藏或显示形成优先状态，自动行为不得推翻该选择。
_Avoid_: 全屏隐身, 全屏避让

**显存占用**:
GPU 专用显存中已使用容量占显存总容量的百分比。
_Avoid_: 显存使用量

**网速**:
单位时间内在**物理网卡**上收发的字节量，小窗分别显示下行与上行，单位 `MB/s`、保留一位小数。下行取网卡接收字节计数，上行取发送字节计数；虚拟网卡不参与统计。
_Avoid_: 网络速度, 带宽, 上传下载速度

**物理网卡口径**:
判定哪些网卡参与网速统计的唯一标准：`MIB_IF_ROW2.PhysicalMediumType` 非 `Unspecified`，等价于 `Get-NetAdapter -Physical`。理由与备选判据见 ADR-0004。
_Avoid_: 真实网卡, 硬件网卡, 网卡白名单
