# 贴边时把卡片四周透明边距推出屏幕，使可视卡片紧贴屏幕边

> 状态：Accepted。几何求解在 `electron/src/main/dock.ts`，由 `electron/tests/dock.test.ts` 覆盖。
>
> 本文的约束（透明无边框窗被钳到 ~38 DIP 最小高度）属于 Chromium 软件层而非原生窗口限制，改不掉，只能靠这套透明边距推出方案绕开。


Windows 11（本机 175% DPI）下，透明无边框 Electron 窗口被 Chromium 钳制为最小高度约 38 DIP（宽度另有系统最小跟踪尺寸），而卡片固定为 26px。左右停靠时卡片垂直居中于 38px 窗口，上下各留约 6px 透明空隙，视觉上"离边框太远"；此前尝试把窗口本体缩小到与卡片同高（26px）不可行。

## 决策

- 窗口比卡片四周各多留 **6px 透明边距**（宽 = 卡片宽 + 12；高因 OS 钳制天然多 ~12px），卡片在窗口中双向居中。
- 贴边检测改为返回**所有**距离 ≤ 8px 的屏幕边（支持同时贴两条边，如左上角），掩码（如 `top-left`）存入 `widget.docked`。
- 定位时把贴中的每条边连同透明边距**推出屏幕**，使**可视卡片**正好贴住该边；卡片自身仍保留 1px 透明安全边框。
- 渲染端不再按 dock 方向做 `align-self` 锚定，贴边定位全部由主进程（`dock.ts` 的 `dockedPosition`）完成。

## Considered Options

- **原生 WNDPROC 钩子改写 `WM_GETMINMAXINFO` 让窗口缩到 26px**：实测宽度钳制可解除，但 38px 最小高度是 Chromium 软件层写死，消息钩子无效；且 koffi 回调在消息泵中重入有挂死风险。放弃。
- **`frame:true` + 启动后剥离 `WS_CAPTION`**：窗口可缩到 ~9px，但 Chromium 仍按标题栏预留客户区，页面加载后内容被压成 ~2px；`WM_NCCALCSIZE` 覆写同样无效。放弃。
- **卡片铺满窗口（26→38px）**：可消除空隙，但改变卡片尺寸，违背"卡片保持 26px"的要求。放弃。
- **不透明窗口（下限 31px）**：仍大于 26px，且失去透明圆角/磨砂。放弃。
- **本方案（采用）**：无原生钩子、卡片尺寸不变；代价是贴边侧窗口略超出屏幕（透明、不可见），且沿贴边方向拖动会被吸回（需向屏幕内拖离超过阈值才解除）。
