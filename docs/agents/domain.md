# 领域文档

工程技能探索代码库时，应遵循本文件说明来读取领域文档。

## 开始探索前

- 阅读仓库根目录的 `GLOSSARY.md`；如果存在 `GLOSSARY-MAP.md`，则按它指向的上下文读取相关词汇表。
- 阅读 `docs/adr/` 中与当前工作区域有关的架构决策记录（ADR）。
- 如果这些文件不存在，继续工作即可；不要专门报告缺失，也不要提前建议创建。待术语或决策实际确定时，再由领域建模技能按需创建。

## 文件布局

本仓库采用 single-context（单上下文）布局：

```text
/
├── GLOSSARY.md
├── docs/adr/
└── src/
```

## 使用词汇表

在事项标题、重构建议、假设或测试名称中提及领域概念时，使用 `GLOSSARY.md` 定义的术语，不要改用词汇表明确避免的同义词。

如果需要的概念尚未列入词汇表，先判断是否引入了项目未使用的新说法，或是否确有词汇表缺口；后者可记录下来，交由领域建模技能处理。

## 发现 ADR 冲突

如果输出与现有 ADR 冲突，应明确指出冲突的 ADR 及原因，不要默默覆盖原决策。
